# PLA-1897 notes

- `escape-sso/vercel` exports `vercelSSO(config?, options?)`; `options.fetch` is undocumented and exists for tests. Each call holds its own lazily created `createSSO` instance.
- `vercelMatcher` is exported for programmatic use. Vercel reads `config.matcher` statically, so `middleware.ts` must write the literal `export const config = { matcher: ['/((?!_vercel).*)'] };`.
- Identity goes upstream only via `next({ request: { headers } })`, which emits `x-middleware-request-*` and `x-middleware-override-headers`. The email header is never set on the response.
- Pass and skip paths remove `x-escape-sso-email` from the override list. Whether Vercel then drops an incoming copy of that header on the upstream request is not verified here; it needs a check on the preview.
- The skip path runs only when `skipOnVercelPreview` is set, `VERCEL_ENV === 'preview'`, and `SSO_GOOGLE_CLIENT_ID` is unset in the environment. A `clientId` passed as the argument does not stop the skip.
- `typecheck` also checks `examples/vercel-static/middleware.ts` through `tsconfig.examples.json`, which maps `escape-sso/vercel` to `src/adapters/vercel.ts`.
- Any error thrown in the adapter answers 500 with `Cache-Control: no-store`.
