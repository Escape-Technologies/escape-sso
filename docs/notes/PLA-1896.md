# PLA-1896 notes

- `createSSO(config, options)` caches issuer discovery per handler instance and injects `fetch` into discovery, token exchange, and JWKS verification.
- `oauth4webapi` validates token response claims and nonce. `validateApplicationLevelSignature` verifies the ID token signature with the injected JWKS fetch.
- Pending return paths are checked on login and checked again before the callback redirect. Invalid pending state ends on a terminal 403 page.
- Callback failures use the same restricted-account page and clear the pending cookie. Logout clears only the session cookie and returns a sign-in page.
- Gate-created responses use `Cache-Control: no-store`; K3 uses non-sliding session JWT expiry.
- A rejected discovery promise is evicted from the instance cache so later requests can retry after a transient issuer outage.
